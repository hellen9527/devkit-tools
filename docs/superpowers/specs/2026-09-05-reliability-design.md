# DevKit 首版可靠性设计

用户在上一轮评估后已确认五阶段实施顺序，采用评估中的产品方向。首批以现有 14 工具的正确性和手机可用性为范围；不重做品牌、不扩工具数量。

实现选项：继续修改巨型单文件最快但不利后续测试；完整框架重写成本高且不必要；采用渐进拆分（选择）：先回归测试和修复，再共享 CSS/JS 与静态页面生成。输入始终留在浏览器，静态部署不引入后台。

第一批：JSON 用词法 token 保留原始数字、键顺序与字符串；Regex 使用可中止的独立 worker 并保留真实 flags 语义；HTML 按 Unicode 码点和标准实体处理；JWT 区分 exp/nbf/iat；Cron 明确五字段 cron 语义及日期 OR 匹配，严格校验并从下一分钟开始；curl 明确静态字面量转换边界，不支持的 shell 计算应报错；CIDR/颜色/时间戳严格校验及保真。

视觉：保留深色橙色强调，编辑区更宽、文字更清楚；手机表格堆叠，控件不横向溢出，导航正确管理焦点。工具输入不默认保存。先正确性，再操作便利。

验证：Node 原生 test runner 检查已复现问题和真实输入输出；浏览器检查桌面与手机操作、剪贴板、Worker 结果及无新控制台错误。回归测试和运行说明提交到 Git，阶段状态保存在 docs/PROGRESS.md。

验收：不再静默更改大整数或 Unicode；Regex 普通匹配可用且超时可恢复；日期、Token、网络边界结果正确；390px 页面无横向溢出。第二阶段单独计划生成页面及 SEO。
